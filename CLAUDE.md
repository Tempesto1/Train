# Рабочие веса — дневник тренировок

Личное веб-приложение (PWA) для записи силовых тренировок и кардио по неделям и сравнения рабочих весов с прошлыми неделями. Сайт публикуется через GitHub Pages из ветки `main`, папка `/` (корень): https://tempesto1.github.io/Train/ . Файлы в корне отдаются как есть, без сборки (`.nojekyll`).

## Структура
```
index.html            оболочка: разметка экранов, подключение стилей и js/app.js
css/
  tokens.css          цвета, шрифты, светлая/тёмная тема
  base.css            сброс, блины, верхняя панель, кнопки, уведомления, подсказки
  scale.css           главный экран — шкала недель
  week.css            экран недели
  editor.css          экран записи тренировки
  profile.css         окно «Мои данные»
  progress.css        экран прогресса и графики
js/                   ES-модули, браузер грузит их напрямую
  app.js              точка входа: переключение экранов, общий обработчик нажатий, запуск
  state.js            общее состояние S и профиль P (P меняется только через Object.assign)
  config.js           справочники: дни, группы мышц, библиотека упражнений, кардио
  util.js             DOM, даты (ISO-недели), числа и форматирование
  model.js            расчёты: лучший подход, сравнение с прошлым разом, статистика недель
  store.js            localStorage, база артефакта Claude, очередь записей, резервные копии
  bus.js              шина событий (changed, profile, save-state) вместо круговых импортов
  ui.js               строка статуса и всплывающие сообщения
  views/              scale.js, week.js, editor.js, progress.js, charts.js, profile.js
manifest.webmanifest, icons/   PWA
sw.js                 создаётся сборкой — руками не править
tools/build.js        сборка (см. ниже); tools/icon.js — рисует icons/*.png (нужен playwright)
```
Блоки `<!-- pwa:start -->…<!-- pwa:end -->` в `index.html` нужны только версии-приложению и вырезаются при сборке для claude.ai.

## Как выпустить новую версию
1. `npm install` (один раз за сессию, ставит esbuild).
2. Править файлы в `css/`, `js/`, `index.html`.
3. `npm run build` пересоздаёт `sw.js` (новая версия кэша, иначе у пользователей останется старое) и `dist/artifact.html` (всё одним файлом для claude.ai; `dist/` не коммитится).
4. Проверить: локальный сервер (`python3 -m http.server`) на ширине телефона 390px, в светлой и тёмной теме, без ошибок в консоли. Новые импорты проверять на `no-undef` (eslint): esbuild не ловит пропущенный импорт.
5. Закоммитить и запушить в `main`. Pages обновится примерно за минуту, у пользователей новая версия подтянется при следующем запуске (`sw.js` идёт сначала в сеть, а без сети или при ответе дольше 3,5 с берёт кэш).
6. Если нужно, обновить артефакт на claude.ai из `dist/artifact.html`: https://claude.ai/artifact/7ikWVGZR5ncMebp28f1VWs (его база: читать и писать может только владелец).

## Данные
- Версия-приложение хранит всё в `localStorage` устройства: `rv.sessions.v1` (массив тренировок) и `rv.profile.v1` (`{weight, age}`). На сервер ничего не уходит. **Формат хранения менять только с миграцией старых записей**: потеря данных у пользователя необратима.
- Версия на claude.ai хранит те же документы в базе артефакта: `sessions/<год>-W<нед>_<тип>` и `profile/me`.
- Перенос между версиями: «Прогресс» → «Скопировать данные» / «Восстановить из копии» (JSON `{profile, sessions}`).

## Модель
- Неделя: ISO, начинается с понедельника, ключ `2026-W45`. Тренировка: `{week, type, date, exercises|cardio, note}`, где `type` ∈ `back | legs | chest | cardio`; id = `<week>_<type>`.
- Дни: спина + бицепс; ноги (+ плечи по желанию); грудь + трицепс (+ плечи по желанию); кардио.
- Упражнение: `{name, muscle, bw, sets}`. Обычный подход: `{w, r}`. С собственным весом (`bw: true`): `{x, r, bw}`, где `x` — доп. вес (пусто = 0), `bw` — вес тела на момент подхода; в расчётах берётся `bw + x`.
- «Совокупность весов» = сумма вес × повторы за неделю. Пустые поля кардио считаются нулём.
- Прогресс по упражнению: лучший рабочий вес, а при равном весе — больше повторов.
